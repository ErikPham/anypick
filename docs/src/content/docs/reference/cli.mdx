The command name is `anypick`. During the current development preview, run the
same command tree from a checkout as `pnpm dev <arguments>`; for example,
`pnpm dev list accounts`. No supported CLI or native-app installer is currently
published.

The native macOS application is a separate app-owned target. It launches its
bundled Go service itself and does not need this CLI to parent it.

## Global flags

Valid on every command.

| Flag | Effect |
| --- | --- |
| `--json` | Machine-readable output |
| `-v, --verbose` | Verbose logging |
| `-q, --quiet` | Minimal output |
| `--dry-run` | Print the plan; write nothing |
| `--reveal` | Show secrets — dangerous |
| `--no-input` | Never prompt, even on a TTY |
| `-y, --yes` | Skip destructive confirmations |
| `--trace` | Print internal step names, without secrets |
| `--tui` | Open the Terminal UI for this run |
| `--tray` | Select the compatibility tray surface for this source CLI run |

## Bindings

```bash
anypick use [client] [--with <source>] [--current]
                     [--model <id>] [--save <name>]
anypick run [client] [--with <source>] [--model <id>]
anypick current [client]
anypick link <client> [--with <source>] [--model <id>]
anypick unlink [client]
anypick reset [client]
```

| Command | Description |
| --- | --- |
| `use` | Set what a client uses by default |
| `use --current` | Re-apply the stored global binding |
| `use --save <name>` | Bind, and also save the result as a preset |
| `run` | Launch a client with its effective binding |
| `current` | Show effective bindings |
| `link` / `unlink` | Project-scoped bindings for the current directory |
| `reset` | Remove AnyPick-managed configuration for a client |

`--with` accepts an account (`grok/work`), a gateway name, a pool
(`pool:gemini`), the Proxy Hub (`hub:default`), or a preset (`@work-stack`).

<Aside type="caution" title="Non-interactive use">
`use <client>` requires `--with` or `--current`. With neither, and no TTY to
prompt on, it exits `2` instead of guessing.
</Aside>

## Inventory

```bash
anypick list [accounts|gateways|clients|presets]
anypick providers
anypick clients
```

`list` with no argument prints all four. `ls` is an alias.

## Adding sources

```bash
anypick add account [provider] [--current] [--new]
    [--name <name>] [--source <id>] [--auth-method <id>]
    [--api-key [key]] [--region <region>]
    [--credential <kind> --secret [secret]]
    [--option <key=value...>]
anypick add gateway [name] --provider <id> --endpoint <url>
    [--api-key <key> | --api-key-env <var>]
    [--model <id>] [--models <id...>]
```

`--current` snapshots the login that is live now. `--new` uses an available
provider-owned browser sign-in and saves its resulting native credential;
otherwise it stashes the current login and prints the manual continuation.
Official methods are preferred, while `--auth-method <id>` can select any method
the provider declares, including a community method. `--source <id>` picks an
explicit native store for a multi-source provider. `--api-key` is the backwards-compatible Kiro
shortcut and prompts for the value when it is omitted; `--region` pins its API
region. Plugin providers use `--credential <kind>`, `--secret`, and one or more
provider-declared `key=value` qualifiers after `--option`. Omit the `--secret`
value to use a masked prompt.

## Accounts

```bash
anypick account list [provider]
anypick account refresh <provider> [name] [--all]
anypick account remove <provider> <name>
anypick account export <provider> <name> -o <file>
anypick account import <provider> <name> -i <file> [-f]
```

`refresh` with no name refreshes the live login. `rm` is an alias for `remove`,
`ls` for `list`.

## Gateways

```bash
anypick gateway list
anypick gateway show <name>
anypick gateway edit <name> [--endpoint <url>] [--api-key <key>]
    [-m <id>] [--models <id...>]
anypick gateway remove <name>
```

`show` masks the API key unless you pass the global `--reveal`.

## Presets

```bash
anypick preset list
anypick preset show <name>
anypick preset remove <name>
```

Preset names are written without the `@` here; the `@` prefix is only how you
reference one in `--with`.

## Proxies

```bash
anypick proxy
anypick proxy status [provider] [name]
anypick proxy start [provider] [name] [-p <port>] [--host <host>]
anypick proxy stop [provider] [name]
anypick proxy enable <provider> <name> [-p <port>] [--host <host>]
    [--auth-mode auto|public|api] [--no-start]
    [--oauth-source auto|gemini-cli|antigravity]
anypick proxy config <provider> <name> [-p <port>] [--host <host>]
    [--auth-mode …] [--oauth-source …] [--no-restart]
anypick proxy disable <provider> <name>
anypick proxy logs <provider> [name] [-n <lines>] [-f]
```

`config` has the alias `set`. `--host` defaults to `127.0.0.1`. Omitting `-p` on
`enable` takes the first free port. `stop` with no arguments stops every running
account proxy.

### Pools

```bash
anypick proxy pool status <provider>
anypick proxy pool enable <provider> [-p <port>] [--host <host>] [--no-start]
anypick proxy pool member <provider> <account> <on|off>
anypick proxy pool disable <provider>
```

### Proxy Hub

```bash
anypick proxy hub status
anypick proxy hub enable [-p <port>] [--host <host>] [--start]
anypick proxy hub source <provider> <account> <on|off>
anypick proxy hub owner <model> <provider> <account>
anypick proxy hub preview
anypick proxy hub start
anypick proxy hub stop
```

Bind with `--with hub:default` after at least one source is enabled. `owner`
picks which account wins when two sources advertise the same model id;
`preview` refreshes catalogs and prints routes plus conflicts.

## Plugins

```bash
anypick plugin list
anypick plugin add <dir|bundled:name>
anypick plugin enable <name>
anypick plugin disable <name>
anypick plugin trust <name>
anypick plugin remove <name>
```

`add` installs a local directory **disabled**. `enable` is the trust decision and
prompts; it needs the global `-y` when there is no TTY. `trust` re-pins the
package digest after the plugin's code changes. See
[Plugins](/docs/guides/plugins).

## Source CLI surfaces and compatibility supervisor

```bash
anypick tui
anypick tray
anypick tray start
anypick tray status
anypick tray stop
```

`anypick tui` always opens the [Apps / Terminal UI](/docs/guides/terminal-ui).
The `tray` command family remains in the TypeScript source tree as a compatibility
path while the native cutover is completed. `start`, `status`, and `stop`
inspect or control that compatibility supervisor and the proxies it owns.

These commands do not define native-app ownership. The macOS app resolves and
starts `Contents/Helpers/anypick-core`, keeps the menu-bar quick panel inside the
same application, and stops the helper on explicit app Quit. See
[macOS app and menu bar](/docs/guides/tray).

## Update command during the preview

```bash
anypick update           # legacy npm-channel behavior
anypick update --check   # query only; install nothing
```

The command still implements the existing npm-channel compatibility behavior:
it compares the running version with the registry's `latest` tag and can invoke
npm for that exact version. It does **not** update `AnyPick.app`, install a
bundled Go helper, or establish that a supported release currently exists.

For this development preview, update the source checkout through its version
control workflow and rerun `pnpm install`. `--check` remains non-mutating and
supports `--json`:

```bash
anypick update --check --json
```

```json
{ "current": "1.0.0", "latest": "1.1.0", "updateAvailable": true, "updated": false }
```

<Aside type="caution" title="Not a native app updater">
Do not use `anypick update` for an Xcode-built app. Signed app updates and all
installer channels remain planned distribution work.
</Aside>

## Shell completion

```bash
anypick completion zsh     # also: bash | fish
```

Add it to your shell startup file, or evaluate it directly:

```bash
source <(anypick completion zsh)
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Operational failure |
| `2` | Invalid usage — missing client or source, bare `use` without a TTY |
| `3` | Not found |
| `4` | Auth required |
| `5` | Capability conflict, unsupported transport, or no binding |
| `6` | Health failure |
| `7` | Missing required dependency, such as an external proxy binary |
| `8` | Malformed or untrusted import envelope |
| `9` | Import exceeds size or file-count limits |
| `130` | Cancelled with SIGINT |

## Environment variables

### AnyPick

| Variable | Effect |
| --- | --- |
| `ANYPICK_HOME` | Data directory. Default `~/.anypick` |
| `ANYPICK_UI=tui\|tray` | Override the saved surface for a bare compatibility CLI run |
| `ANYPICK_NO_PLUGINS=1` | Skip loading plugins entirely |

| `ANYPICK_DEBUG=1` | Echo internal events to stderr |
| `NO_COLOR` | Drop all color; glyphs still carry state |

### Provider overrides

| Variable | Effect |
| --- | --- |
| `OPENCODE_PROXY_UPSTREAM` | Override the OpenCode upstream base URL |
| `OPENCODE_MODEL_METADATA_URL` | Override model metadata source; `none` disables enrichment |
| `GEMINI_PROXY_UPSTREAM` | Override the Gemini upstream base URL |
| `GEMINI_CODE_ASSIST_UPSTREAM` | Override the Code Assist endpoint |
| `GROK_PROXY_UPSTREAM` | Override the Grok upstream base URL |
| `KIROLINK_BIN` | Path to an external `kirolink` binary |
| `CLAUDE_BINARY`, `CODEX_BINARY`, `KIRO_BINARY` | Launch a specific client binary |

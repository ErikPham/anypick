title: Plugins
description: What the plugin registry does in a native AnyPick build — install, pin, enable — and why no plugin code is executed.
---

A native AnyPick build keeps the plugin **registry** but not the plugin
**host**. You can install a plugin, pin it to a whole-package digest and enable
it by name; nothing loads or runs its code.

<Aside type="caution" title="No plugin code runs in a native build">
Earlier releases loaded third-party plugin modules into the AnyPick process.
Native builds do not: there is no plugin host, so an enabled plugin grants
third-party code no access to your credentials today. See
[ADR-0021](https://github.com/outof0/anypick/blob/main/adr/0021-plugin-host-removed-from-native-builds.md).
Treat this as the current state, not a permanent guarantee — if a Go-native
executor lands, this page and `SECURITY.md` change in the same commit.
</Aside>

## What still works

```bash
anypick plugin add ./acme-provider   # recorded, disabled, digest pinned
anypick plugin list
anypick plugin enable acme-provider  # prompts — records the trust decision
```

`add` never enables. The plugin is recorded in AnyPick's registry either way.

```
  off  acme-provider        1.0.0      82aae3b7898d
    /Users/you/src/acme-provider
```

The short hex is a SHA-256 digest of the whole plugin package (manifest and
every shipped file under the directory). AnyPick recomputes and compares it on
every load, so a package that changed since you approved it is refused:

```
  fail acme-provider        1.0.0      82aae3b7898d
    plugin acme-provider has changed since you trusted it
    → anypick plugin trust acme-provider
```

That is intentional friction, not a cache miss — the digest is what you
approved. Review the diff, then re-pin with `anypick plugin trust acme-provider`.

## What changed

Because there is no host, every candidate reports a load failure rather than
loading. This is deliberate: a silent empty list would look like a healthy
plugin set, so `anypick doctor`, `plugin list` and the desktop app all surface
the reason instead.

```bash
anypick plugin disable acme-provider  # keep it installed, stop considering it
anypick plugin remove acme-provider   # uninstall
ANYPICK_NO_PLUGINS=1 anypick doctor   # skip every plugin for one run
```

## Compatible providers are built in

The providers that used to ship as the `bundled:popular-providers` pack are now
registered directly by the Go engine. You do not install anything — they are
available as managed accounts out of the box.

```bash
# Omit the --secret value to use the masked prompt.
anypick add account kimi --credential subscription-key --secret --name personal
anypick add account minimax --credential api-key --secret --name paygo \
  --option profile=global
anypick add account mimo --credential subscription-key --secret --name europe \
  --option profile=europe
```

| Provider | `api-key` | `subscription-key` profiles |
| --- | --- | --- |
| Kimi | Open Platform (`global`, `china`) | Kimi Code membership |
| GLM | BigModel / Z.AI (`china`, `global`) | GLM Coding Plan (`china`, `global`) |
| MiniMax | pay-as-you-go (`china`, `global`) | Token Plan (`china`, `global`) |
| MiMo | pay-as-you-go | Token Plan (`china`, `singapore`, `europe`) |
| DeepSeek | platform API | — |
| Qwen | Model Studio (`china`, `singapore`, `us`) | Coding Plan / Token Plan |
| Ark | Volcengine / BytePlus (`china`, `global`) | Coding Plan (`china`, `global`) |
| TokenHub | Tencent pay-as-you-go | Tencent Coding Plan |
| OpenRouter | multi-model API | — |
| GroqCloud | inference API | — |
| Mistral | La Plateforme API | — |
| Together | inference API | — |
| Fireworks | serverless API | — |
| Cerebras | inference API | — |
| SiliconFlow | inference API | — |
| NVIDIA NIM | hosted NIM API | — |

Subscription keys stay behind the same authenticated local proxy and pool as
API keys. The proxy keeps the real client `User-Agent`; it does not import a
consumer website session or pretend to be another coding tool. Use a subscription
only for the interactive coding scenarios its provider permits. OpenRouter,
GroqCloud, and Fireworks use their documented native Responses endpoints; other
OpenAI-compatible profiles translate Responses through Chat Completions.

## Adding a provider today

Until a Go-native executor exists, adding a provider means building AnyPick
from source and registering it in-tree. The contributor guide covers what a
good provider implements — including its model policy, which is what keeps your
provider from inheriting another vendor's model ids.

AnyPick's macOS surface is one native SwiftUI application. Its main window is
the full management surface; its menu-bar item is a compact quick panel of the
same running app.

<Aside type="caution" title="Source preview, not a published app">
The native target is available in this repository for development and testing.
There is not yet a signed/notarized DMG, Homebrew Cask, or supported macOS
download. The release targets in ADR 0020 are planned distribution work, not
currently available artifacts.
</Aside>

## The app owns its service

The lifecycle is app-first:

```text
AnyPick.app
├── main window
├── menu-bar quick panel
└── Contents/Helpers/anypick-core desktop-service --stdio
```

On launch, the app resolves `anypick-core` relative to its own bundle and starts
it as a child. A version and capability handshake completes before mutations
are enabled. Frames are bounded and stdout is protocol-only. Unexpected exits
use a bounded restart policy; an incompatible or repeatedly failing helper puts
the UI into a degraded state instead of silently switching to another engine.

The app does **not** find the service on `PATH`, connect to a permanent daemon,
or ask an installed Node process to own it. A future distributed build will
include the helper; users will not compile Swift or Go at runtime.

Closing the main window leaves the application and its local services running.
Choose **Quit AnyPick** or the quick panel's **Quit** button to stop the bundled
service gracefully and terminate the app.

## Run the current source target

Requirements: macOS 14+, Xcode, and a Go launcher capable of selecting the
toolchain pinned by `go/go.mod`.

```bash
open src/macos/AnyPick.xcodeproj
```

Select the shared **AnyPick** scheme and Run. Xcode builds the existing Swift
tree in `src/macos/` and installs the Go executable at
`AnyPick.app/Contents/Helpers/anypick-core` as part of the app build.

For isolated UI work, use the in-memory fixture:

```bash
pnpm macos:design
pnpm macos:design --flow tray-attention
pnpm macos:design:check
```

The fixture's `swiftc` command is a repository development tool. It is not the
production launch path and is not an end-user prerequisite.

## Main window

The regular Dock app opens a System Settings-style management window with these
sidebar destinations:

| Destination | Purpose |
| --- | --- |
| **Overview** | Setup progress, attention, and service summary |
| **Apps** | Current client routes and source selection |
| **Accounts & APIs** | Saved native logins and API gateways |
| **Proxy Hub** | Unified local endpoint, sources, models, and lifecycle |
| **Proxies** | Per-account translators and their lifecycle |
| **Activity** | Recent events and bounded live logs |
| **Account Backups** | Export, inspect, import, and restore saved accounts |

App-wide options live in the native **Settings** scene (<kbd>⌘,</kbd>), not in
the main sidebar. Current panes cover General, Usage, Proxies, and Security.

In **Accounts & APIs → Add Account**, a provider may expose a provider-owned
browser sign-in. AnyPick launches that method and then verifies and saves the
provider's resulting native credential; it does not imitate the provider's
OAuth pages or ask for the account password.

## Menu-bar quick panel

The menu-bar window provides quick access without becoming a second app. It can:

- show ready/attention state and search saved accounts or destinations;
- show active app routes and supported usage information;
- switch a supported app to another compatible source;
- expand Proxy Hub and per-account proxy rows for start, stop, and restart;
- open the full AnyPick window or quit the application.

Detailed configuration stays in the main window. The menu-bar icon may show an
attention marker when a route or service needs review. First-run and degraded
states use the same production view hierarchy as the ready state.

## Launch at login

The native Settings toggle uses macOS `SMAppService`. If macOS requires manual
approval, AnyPick directs the user to **System Settings → General → Login
Items**. It does not install a custom LaunchAgent from the UI.

## CLI compatibility during cutover

The TypeScript source tree still exposes these compatibility commands:

```bash
pnpm dev tray
pnpm dev tray start
pnpm dev tray status
pnpm dev tray stop
```

They exercise the existing source supervisor and are useful while the cutover
is being completed. They are not the lifecycle contract of the native app and
do not describe a published installer. Native-app lifecycle is controlled by
launching, closing, reopening, and explicitly quitting `AnyPick.app`.

The terminal UI remains available from source with `pnpm dev tui`. Its tray
runtime shortcuts belong to that compatibility path; closing the TUI does not
implicitly quit a separately launched native app.

## Security boundary

Credentials and per-instance proxy bearer tokens remain in the Go service.
Desktop snapshots contain display-safe state and opaque action identifiers, not
raw saved credentials. The helper's stdio connection is private to its owning
app and is not a documented integration API.

See [Apps & Terminal UI](/docs/guides/terminal-ui) for the source CLI workflow
and [Proxies](/docs/guides/proxies) for proxy and Hub behavior.
